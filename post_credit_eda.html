Starting with data quality

The notebook begins with the main application table, checks null rates and column types, and removes 64 columns with more than 30% missing values. It imputes missing annuity values with the median, reviews unusual category values, and creates income and credit bands for comparison.

The outcome is interpreted as 0 = no recorded payment difficulty and 1 = payment difficulty. I then split the records by outcome and compare applicant attributes, distributions, and Spearman correlations.

What the analysis surfaces

  • Credit amount and annuity move together in both outcome groups (reported Spearman correlations: 0.83 for outcome 0 and 0.81 for outcome 1).
  • Income has a more moderate association with annuity and credit amount in the saved correlation tables.
  • The second part cleans previous-application categories, joins them to current applications by applicant ID, and explores how earlier loan purpose and amount vary across current outcomes.

The notebook is an EDA project; it does not train or validate a default-prediction model. Its useful output is a set of questions and patterns for a more careful modeling or policy analysis.

Interpretation note. The notebook removes records where organization type is “XNA” (about 18% of the rows at that step), which can change the population represented. Its written note also incorrectly says most records are outcome 1; the intended definition and the source data indicate payment difficulty is the minority class. The joined previous-application table can contain multiple rows per applicant, so those charts should be interpreted at the application level unless aggregated by person.

Next steps

Keep unknown organization values as an explicit category, report outcome rates with denominators rather than raw counts, aggregate prior applications at applicant level when the question is about people, and rerun the analysis from documented source files.
