Candidate salary & location analysis

Can candidate profile information help estimate salary—and can it predict a preference for Delhi NCR? I explored both questions as separate modeling tasks.

Candidate profiles, skills, education, work history

The questions

The capstone notebook turns a large candidate-profile table into two analyses. The first estimates cleaned salary values from profile characteristics. The second labels whether a candidate’s preferred location falls within Delhi, Noida, Gurgaon, or Faridabad.

How I approached it

  1. Profile and clean. Inspected column types and missingness; removed rows missing all three highest-education descriptors; filled selected categorical fields and numeric gaps; and grouped locations into a focused city list plus “Other.”
  2. Represent profile details. Normalized comma-separated skills, retained a limited set of frequent skills, encoded selected categories, and reduced high-cardinality fields before modeling.
  3. Estimate salary. Compared Ridge regression, Random Forest, and XGBoost using a validation split and a separate supplied test file.
  4. Classify location preference. Built a binary Delhi NCR label, addressed training imbalance with SMOTE, and compared Logistic Regression, Random Forest, and XGBoost, including a tuned XGBoost model.

Results recorded in the notebook

0.239XGBoost salary test R²
6.32Salary test RMSE in the notebook’s target units (labelled LPA)
0.547Tuned XGBoost location test ROC AUC

For salary regression, XGBoost has the best saved test score of the three models, though its R² indicates substantial salary variation remains unexplained. For location preference, the validation ROC AUC is higher than the saved test ROC AUC, and the test set contains only 42 positive examples.

Evaluation note. These are notebook-reported results, not freshly reproduced estimates. The test set’s location-label distribution differs sharply from validation, and some categorical encodings are learned independently on the test data. I would standardize preprocessing using training-only mappings and investigate the distribution shift before presenting the location model as reliable.

What I learned

This project made data preparation the central modeling challenge: candidate skills and education create high-cardinality features, while a location label can be easy to define but difficult to generalize. The next iteration should package preprocessing into fitted pipelines, verify feature alignment, and use a representative holdout set before comparing models.
